## 주요 이슈 및 해결

### 이슈 1: Prisma date 필드 타입 에러
- **문제**: `Invalid value for argument 'date': premature end of input. Expected ISO-8601 DateTime.`
- **원인**: schema.prisma에서 `date DateTime @db.Date`인데 문자열 직접 비교
- **해결**: `new Date(date)` 변환 추가

### 이슈 2: createdAt 필수 필드 누락
- **문제**: `Argument 'createdAt' is missing.`
- **원인**: schema에 `@default(now())` 없음
- **해결**: `createdAt: getNowKST()` 명시적 추가

### 이슈 3: 통계 데이터가 0으로 나옴
- **문제**: DB에서 가져온 date는 Date 객체인데 문자열과 직접 비교
- **해결**: `r.date.toISOString().split('T')[0] === date` 변환 후 비교

### 이슈 4: 점수가 비정상적으로 큼 (375점 등)
- **문제**: 25점을 5점 기준 환산 공식 적용 (25/5*100 = 500점)
- **해결**: 점수 그대로 합산, 환산 제거

### 이슈 5: 무조건 7일로 나눔
- **문제**: 검색 기간이 5일이든 7일이든 무조건 7로 나눔
- **해결**: `weekDates.length`로 실제 검색일 수만큼 나눔

### 6. Diet 기록 비즈니스 로직 구현
- **파일**: `src/tracking/services/records.service.ts` - `createDietRecordImpl()`
- **비즈니스 규칙**:
  - BREAKFAST: 1회/일 (100점)
  - LUNCH: 1회/일 (100점)
  - DINNER: 1회/일 (100점)
  - SNACK: 최대 3회/일 (0점)
  - MIDNIGHT_SNACK: 최대 3회/일 (0점)
- **검증 로직**:
  ```typescript
  // 같은 날짜의 모든 식단 기록 조회
  const todayRecords = await tx.userRecord.findMany({
    where: { userId, recordType: 'DIET', date: new Date(date) }
  });

  // 같은 식사 타입 카운트
  const sameDietTypeCount = todayRecords.filter(
    r => r.metadata?.diet === dietType
  ).length;

  // 제한 체크 및 ConflictException 발생
  if (['BREAKFAST','LUNCH','DINNER'].includes(dietType) && sameDietTypeCount >= 1) {
    throw new ConflictException(`오늘 이미 ${dietType} 기록을 완료했습니다`);
  }
  if (['SNACK','MIDNIGHT_SNACK'].includes(dietType) && sameDietTypeCount >= 3) {
    throw new ConflictException(`오늘 ${dietType} 기록은 최대 3회까지만 가능합니다`);
  }
  ```
