
- **일요일 23:59:59 → 월요일 00:00:00**
- 매주 월요일이 시작되는 정각에 실행

## 2. 영양제 7일치 자동 생성 로직 추가

### 배경 및 개념
- 영양제 기록은 다른 기록(운동, 식단 등)과 성격이 다름
- **다른 기록**: 과거에 뭘 했다 (저장 시점의 과거 데이터)
- **영양제 기록**: 앞으로 7일간 이걸 먹을 거다 (미래 루틴 예약)
- "기록/통계"라기보다는 **"미래의 영양제 루틴"** 개념

### 처리 흐름
1. **월요일 00:00 배치 실행**
2. **NEWCOMER → CHALLENGER 상태 변경**
3. **영양제 7일치(월~일) 데이터 생성**
   - `user_supplement_routine` 테이블에서 사용자의 활성 영양제 조회 (예: 3개)
   - 월요일 ~ 일요일까지 7일 × 영양제 3개 = **총 21건 생성**
   - 모두 `false` 상태로 생성 (아직 안 먹음)

### 데이터 구조
```sql
INSERT INTO public.user_records
(user_id, user_challenge_id, record_type, metadata, created_at, updated_at, "date")
VALUES(
  1,                    -- 사용자 ID
  NULL,                 -- 챌린지와 무관
  'SUPPLEMENTS',        -- 영양제 기록
  '{
    "productId": 1,
    "morning": false,
    "afternoon": false,
    "evening": false
  }'::jsonb,
  '2025-11-25 00:00:00.000',
  '2025-11-25 00:00:00.000',
  '2025-11-25'
);
```

### 핵심 포인트
- `user_challenge_id`: **NULL** (영양제는 챌린지와 무관)
- `record_type`: **'SUPPLEMENTS'**
- `metadata`:
  - `productId`: 영양제 상품 ID
  - `morning/afternoon/evening`: 먹음 여부 (초기값 false)
- `max_count` 불필요: `products` 테이블의 `product_info`에 1일 복용 정보 이미 존재

### 구현 코드
**파일:** `src/challenge/challenge-scheduler.service.ts`

```typescript
/**
 * 영양제 기록 7일치 생성 (월요일 ~ 일요일)
 */
private async createWeeklySupplementRecords(
  tx: any,
  userId: number,
  baseDate: Date,
) {
  // 1. 사용자의 활성화된 영양제 루틴 조회
  const supplementRoutines = await tx.userSupplementRoutine.findMany({
    where: {
      userId,
      isActive: true,
    },
    orderBy: {
      displayOrder: 'asc',
    },
  });

  if (supplementRoutines.length === 0) {
    this.logger.warn(`영양제 루틴이 없습니다: userId=${userId}`);
    return;
  }

  const recordsToCreate = [];

  // 2. 월요일부터 일요일까지 7일
  for (let dayOffset = 0; dayOffset < 7; dayOffset++) {
    // KST 기준 날짜 생성 (중요!)
    const recordDate = getNowKST();
    recordDate.setDate(baseDate.getDate() + dayOffset);
    recordDate.setHours(0, 0, 0, 0); // 00:00:00 (KST)

    // 3. 각 영양제마다 기록 생성
    for (const routine of supplementRoutines) {
      recordsToCreate.push({
        userId,
        userChallengeId: null,
        recordType: 'SUPPLEMENTS',
        metadata: {
          productId: routine.productId,
          morning: false,
          afternoon: false,
          evening: false,
        },
        date: recordDate,
        createdAt: getNowKST(),
        updatedAt: getNowKST(),
      });
    }
  }

  // 4. 한 번에 모든 레코드 생성
  await tx.userRecord.createMany({
    data: recordsToCreate,
  });

  this.logger.log(
    `✅ 영양제 기록 생성 완료: userId=${userId}, 총 ${recordsToCreate.length}건`
  );
}
```

### KST 시간 처리 주의사항
```typescript
// ❌ 잘못된 방법 (UTC 기준)
const recordDate = new Date(baseDate);

// ✅ 올바른 방법 (KST 기준)
const recordDate = getNowKST();
recordDate.setDate(baseDate.getDate() + dayOffset);
```

## 💡 핵심 인사이트

1. **영양제 기록의 특수성**
   - 과거 데이터가 아닌 미래 루틴 개념
   - 먹을 예정을 미리 만들고, 먹었을 때 체크하는 방식

2. **배치 최적화**
   - 챌린지 시작일이 월요일만 가능하므로 배치도 월요일에만 실행
   - 불필요한 매일 실행 제거로 리소스 절약

3. **KST 시간 처리의 중요성**
   - `new Date()`는 UTC 기준
   - 반드시 `getNowKST()` 사용하여 한국 시간 기준 처리

4. **데이터 정규화**
   - 영양제 복용 정보(횟수, 개수)는 `products.product_info`에 이미 존재
   - 중복 저장하지 않고 참조하는 방식
