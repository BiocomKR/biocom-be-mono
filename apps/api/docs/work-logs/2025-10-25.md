### 2. 주요 수정 사항

#### 2.1 `date` 필드 제거
**배경**:
- 식단 기록은 일기처럼 당일 기록만 가능
- 전날 기록을 추가하는 개념이 없음
- 서버에서 자동으로 한국 시간 기준 오늘 날짜로 저장

**변경 내용**:
- DTO에서 `date` 필드 제거
- Service에서 `getKoreanToday()` 자동 적용

**Before**:
```typescript
@ApiProperty({
  description: '기록 날짜 (YYYY-MM-DD 형식)',
  example: '2025-09-17',
  required: false
})
@IsOptional()
@IsDateString()
date?: string;
```

**After**:
```typescript
// date 필드 제거됨
```

#### 2.2 `isFasting` 필드 추가
**배경**:
- 점심/저녁 등을 공복으로 유지할 수 있음
- 해당 식사를 건너뛰었는지 표시 필요

**변경 내용**:
- DTO에 `isFasting: boolean` 필드 추가
- Service의 metadata에 `isFasting` 저장

**추가된 코드**:
```typescript
@ApiProperty({
  description: '공복 여부 (해당 식사를 건너뛰고 공복 유지)',
  example: false
})
@IsBoolean()
isFasting: boolean;
```

### 4. 기술적 결정 사항

#### 4.1 imageUrl vs fileUploadId
**논의**:
- `fileUploadId`를 metadata JSON에 저장하면, 조회 시마다 파일 정보를 가져오기 위해 추가 쿼리 필요
- JSON 파싱 후 추가 조인/쿼리는 비효율적

**결정**:
- `imageUrl`을 직접 저장하는 방식 유지
- 프론트엔드에서 파일 업로드 후 받은 URL을 바로 전달

#### 4.2 date 필드 처리
**논의**:
- 클라이언트에서 날짜를 보내야 하는가?
- 어제 식단을 오늘 기록할 수 있는가?

**결정**:
- 당일 기록만 가능 (일기 개념)
- 서버에서 `getKoreanToday()` 자동 적용
- `date` 필드 완전 제거
