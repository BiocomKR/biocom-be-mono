## 6️⃣ 데이터베이스 스키마 단순화 (challenge_schedules → user_challenges 통합)

### 작업 내용
불필요하게 분리된 `challenge_schedules` 테이블을 `user_challenges`로 통합

### 문제점
- `challenge_tickets`: 티켓 구매 기록
- `user_challenges`: 챌린지 진행 상태
- `challenge_schedules`: 챌린지 일정 정보
→ 1:1 관계인데 3개 테이블로 분리되어 복잡도 증가

### 해결 방안
`challenge_schedules` 테이블 삭제하고 모든 일정 컬럼을 `user_challenges`로 이동

### 변경 사항

**1. Prisma Schema 수정**
```prisma
model UserChallenge {
  // 기존 컬럼들...
  startDate       DateTime?  @map("start_date") @db.Date
  deliveryDate    DateTime?  @map("delivery_date") @db.Date
  endDate         DateTime?  @map("end_date") @db.Date
  purchasedAt     DateTime   @map("purchased_at")
  // challengeSchedule 관계 제거
}

// ChallengeSchedule 모델 완전 삭제
```

**2. Migration SQL 작성**
- 파일: `prisma/migrations/20251016_merge_challenge_schedules_to_user_challenges.sql`
- user_challenges 테이블에 컬럼 추가
- 기존 challenge_schedules 데이터 복사
- challenge_schedules 테이블 삭제
- 인덱스 추가

**3. challenge.service.ts 수정**
- `setStartDate()` 함수에서 challengeSchedule.create() 제거
- 모든 일정 정보를 userChallenge.create()에 직접 포함
- 시작일: 00:00:00으로 설정
- 종료일: 23:59:59로 설정
- 배송일: 시작일 -1일 (주말이면 금요일)

**4. 불필요한 제약 조건 제거**
- 초기 구현 시 추가했던 `max_start_date` 컬럼 삭제
- 30일 이내 시작 제약 로직 제거 (사용자 요청에 따라)
- `calculateMaxStartDate()` 함수 삭제
- `isValidStartDate()` 함수의 30일 체크 로직 삭제

**5. 코드 정리**
- 사용하지 않는 import 제거
- DTO에서 maxStartDate 필드 제거
- TypeScript 컴파일 에러 해결

### 최종 스키마 구조
```
user_challenges 테이블
├── activated_at     : 챌린지 활성화 일시 (티켓 사용 시점)
├── start_date       : 챌린지 시작일 (사용자 선택, 00:00:00)
├── delivery_date    : 배송일 (시작일 -1일, 평일만)
├── end_date         : 챌린지 종료일 (시작일 +20일, 23:59:59)
└── purchased_at     : 티켓 구매일
```

### 결과
✅ 성공
- TypeScript 컴파일 에러 0개
- 서버 정상 실행 확인 (포트 10804)
- 테이블 구조 단순화 완료 (3개 → 2개)
