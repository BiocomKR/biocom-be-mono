### 1. 식단 기록 저장 API 수정

#### 1.1 `date` 필드 제거
**배경**:
- 식단 기록은 일기처럼 당일 기록만 가능
- 전날 기록을 추가하는 개념이 없음
- 서버에서 자동으로 한국 시간 기준 오늘 날짜로 저장

**변경 사항**:
- `CreateDietRecordDto`에서 `date` 필드 제거
- `RecordsService.createDietRecord()`에서 `getKoreanToday()` 자동 적용

#### 1.2 `isFasting` 필드 추가
**배경**:
- 점심/저녁 등을 공복으로 유지할 수 있음
- 해당 식사를 건너뛰었는지 표시 필요

**추가된 필드**:
```typescript
@ApiProperty({
  description: '공복 여부 (해당 식사를 건너뛰고 공복 유지)',
  example: false
})
@IsBoolean()
isFasting: boolean;
```

model FoodCategory {
  id           Int      @id @default(autoincrement())

### 6. 성능 최적화

#### 6.1 DB 쿼리 최적화
**Before**:
```typescript
// 쿼리 2번 실행
const highFodmapFoods = await this.getFoodsByCategory('HIGH_FODMAP');
const processedFoods = await this.getFoodsByCategory('PROCESSED');
```

**After**:
```typescript
// 쿼리 1번 실행 후 메모리에서 분류
const foodCategories = await this.getAllFoodCategories();
return {
  highFodmapFoods: foodCategories.highFodmap,
  processedFoods: foodCategories.processed,

```

**교훈**:
> "이런건 씨발 좀 형이 말안해도 알아서 하는 센스를 키워라 새키야"
> - DB 쿼리 2번 실행할 이유가 있냐? 1번에 가져와서 메모리에서 분류해라
> - 비효율적인 코드는 형님이 지적하기 전에 스스로 찾아내서 최적화해라

### 8. 기술적 결정 사항

#### 8.1 imageUrl vs fileUploadId
**논의**:
- `fileUploadId`를 metadata JSON에 저장하면, 조회 시마다 파일 정보를 가져오기 위해 추가 쿼리 필요
- JSON 파싱 후 추가 조인/쿼리는 비효율적

**결정**:
- `imageUrl`을 직접 저장하는 방식 유지
- 프론트엔드에서 파일 업로드 후 받은 URL을 바로 전달

#### 8.2 식품 카테고리 테이블 설계
**결정**: 단일 테이블로 관리
- 카테고리별 분리 테이블 대신 `category` 컬럼으로 구분
- 간단하고 관리하기 쉬움
- 고포드맵/가공식품은 영양학적으로 정해진 분류라 추가될 가능성 낮음
