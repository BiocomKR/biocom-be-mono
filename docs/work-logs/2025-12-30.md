### 변경사항
- CronJob 스케줄 변경: `"0 * * * *"` → `"*/30 * * * *"` (1시간 → 30분 간격)

### 동작 흐름
```
[K8s CronJob] 30분마다 실행
    ↓
[biocom-api] ShippingSyncSchedulerService.handleShippingSync()
    ↓
1. DB에서 동기화 대상 주문 조회 (status NOT IN 완료/취소)
2. 플레이오토 벌크 API 호출 (POST /orders, 최근 30일)
3. logisticsUniq 기준 매칭
4. MQ Job 전송 (order-sync 큐)
    ↓
[biocom-mq] OrderSyncProcessor
    ↓
5. Order 테이블 업데이트 (status, shippedAt, deliveredAt)
6. Shipping 테이블 업데이트 (trackingNumber, courierName, status)
7. OrderStateLog 기록
```

### 상태 매핑
| 플레이오토 상태 | Order.status | Shipping.status |
|----------------|--------------|-----------------|
| 신규주문, 결제완료, 출고대기 | PAID | PENDING |
| 운송장출력 | SHIPPING | READY_FOR_SHIPMENT |
| 출고완료, 배송중 | SHIPPING | IN_TRANSIT |
| 배송완료 | DELIVERED | DELIVERED |
| 구매결정, 판매완료 | COMPLETED | DELIVERED |

## 9. 회원탈퇴 API 구현

### 구현 내용

#### 신규 테이블
- `withdrawn_users`: 탈퇴 회원 정보 보관 테이블
  - userId, name(암호화), mobile(암호화), reason, withdrawnAt

#### API 엔드포인트
- `POST /users/me/withdraw`
- Body: `{ reason?: string }` (탈퇴 사유, 선택)

#### 처리 로직
1. `withdrawn_users` 테이블에 정보 이관 (이름, 휴대폰 - 암호화 상태)
2. `users` 테이블 개인정보 마스킹:
   - name → `탈퇴회원_{userId}`
   - mobile → `deleted_{userId}`
   - email, password, billingKey, customerKey, 환불계좌 정보 → null
3. `is_active` → false, `deleted_at` → 현재시간
4. RefreshToken, PushToken 삭제 (로그아웃 처리)

#### 파일
- `prisma/schema.prisma` (WithdrawnUser 모델)
- `src/users/dto/withdraw.dto.ts`
- `src/users/mypage.service.ts` (withdraw 메서드)
- `src/users/mypage.controller.ts` (엔드포인트)

### is_active 전수조사 결과
- 로그인 시점(이메일/휴대폰)에서 `isActive`, `deletedAt` 체크 **이미 구현되어 있음**
- 탈퇴 회원은 로그인 불가 → 다른 API 접근 원천 차단
- **추가 수정 불필요**
