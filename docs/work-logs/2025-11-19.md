## 🚨 긴급 이슈 해결

### 1. UserConsent 모델 유실 문제 (phone-register API 500 에러)

**문제 상황**
- GKE에서 휴대폰 회원가입 API 500 에러 발생
- 에러: `Cannot read properties of undefined (reading 'create')`
- user_consents 테이블은 DB에 존재하나 Prisma schema에 모델 정의 누락

**원인 분석**
- 11월 17일 schema.prisma 수정 작업 중 UserConsent 모델 누락됨
- schema.prisma.bak (11/17 11:11) 백업 파일에는 모델 존재 확인
- Git 이력 추적 결과: 어딘가에서 오래된 버전의 schema로 덮어씌워진 것으로 추정

**해결 방법**
1. schema.prisma.bak에서 UserConsent 모델 복원
2. User 모델에 userConsents relation 추가
3. `npx prisma generate` 실행하여 Prisma Client 재생성

**UserConsent 모델 구조**
```prisma
model UserConsent {
  id                 Int       @id @default(autoincrement())
  userId             Int       @map("user_id")
  agreeToTerms       Boolean   @map("agree_to_terms")       // 이용약관 (필수)
  agreeToAge14       Boolean   @map("agree_to_age14")       // 만 14세 이상 (필수)
  agreeToPrivacy     Boolean   @map("agree_to_privacy")     // 개인정보 처리방침 (필수)
  agreeToThirdParty  Boolean   @default(false) @map("agree_to_third_party")  // 제3자 정보제공 (선택)
  agreeToMarketing   Boolean   @default(false) @map("agree_to_marketing")    // 마케팅 수신 (선택)
  agreedAt           DateTime  @map("agreed_at")
  createdAt          DateTime  @default(now()) @map("created_at")
  updatedAt          DateTime  @updatedAt @map("updated_at")
  user               User      @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@map("user_consents")
}
```

- 커밋 전 자동 백업 생성
- **누락된 모델 발견 시 커밋 차단**

#### 2. Post-commit Hook (`.git/hooks/post-commit`)
- 커밋 성공 시 자동 백업 생성
- 타임스탬프 형식: `schema.prisma.YYYYMMDD_HHMMSS.bak`

  - 검증 없는 커밋 금지
- **필수 수행 사항**
  - 변경 전 백업
  - 변경 후 검증
  - 테스트 실행
- **Schema 변경 절차** 상세 설명
- **트러블슈팅 가이드**
- **긴급 복구 방법**

## 📦 NestJS 11 호환성 완전 해결

**배경**: 다른 개발자가 `npm install` 시 버전 충돌 발생

**문제 패키지**
- @nestjs/config: 3.1.1 (NestJS 10까지만 지원)
- @nestjs/jwt: 10.2.0
- @nestjs/passport: 10.0.3
- @nestjs/terminus: 10.2.0
- @nestjs/throttler: 5.1.1

**해결**: NestJS 11 호환 버전으로 일괄 업데이트
```bash
npm install @nestjs/config@^4.0.2 @nestjs/jwt@^11.0.1 @nestjs/passport@^11.0.0 @nestjs/terminus@^11.0.0 @nestjs/throttler@^6.2.1
```

**업데이트 결과**
- @nestjs/config: 3.1.1 → 4.0.2
- @nestjs/jwt: 10.2.0 → 11.0.1
- @nestjs/passport: 10.0.3 → 11.0.5
- @nestjs/terminus: 10.2.0 → 11.0.0
- @nestjs/throttler: 5.1.1 → 6.4.0

### Breaking Changes 수정

#### 1. JWT expiresIn 타입 변경
**문제**: `string` 타입이 `number | StringValue`로 변경됨

**수정 파일**
- `src/auth/auth.module.ts`: JwtModule 설정
- `src/auth/auth.service.ts`: JWT sign 호출 5곳

**해결 방법**: `as any` 타입 단언 처리
```typescript
expiresIn: this.configService.jwt.accessTokenExpiresIn as any
```

#### 2. MemoryHealthIndicator 생성자 변경
**문제**: `HealthIndicatorService` 인자 필수

**수정 전**
```typescript
constructor(private readonly logger: LoggerService) {
  super();
}
```

**수정 후**
```typescript
constructor(
  healthIndicatorService: HealthIndicatorService,
  private readonly logger: LoggerService,
) {
  super(healthIndicatorService);
}
```

### 테스트 결과
- ✅ 빌드 성공
- ✅ JWT 인증 테스트 완료
- ✅ 로그인/회원가입 정상 작동

## 🔐 페르소나 업데이트 전용 API 추가

**배경**: PATCH /users/me API가 너무 많은 필드를 변경 가능 (보안 위험)

### 변경 사항

#### 1. 기존 API Deprecated 처리
- **엔드포인트**: `PATCH /users/me`
- **변경**: `@ApiOperation`에 `deprecated: true` 추가
- **Swagger**: `[Deprecated]` 표시

#### 2. 신규 전용 API 추가
- **엔드포인트**: `PATCH /users/me/persona`
- **DTO**: `UpdatePersonaDto` (aiPersonaId만 허용)
- **Service**: `UsersService.updatePersona()` 메서드
- **검증**: 페르소나 존재 여부 및 활성화 상태 체크

**UpdatePersonaDto 구조**
```typescript
export class UpdatePersonaDto {
  @ApiProperty({
    description: 'AI 페르소나 ID',
    example: 1,
    required: true,
  })
  @IsInt({ message: '페르소나 ID는 정수여야 합니다.' })
  @Min(1, { message: '페르소나 ID는 1 이상이어야 합니다.' })
  aiPersonaId: number;
}
```
