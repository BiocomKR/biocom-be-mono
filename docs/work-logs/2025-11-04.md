#### 3.2 지연성 알러지 검사 결과 연동 (외부 API)
- **Service 메서드**: `getAllergyFoods(mobile: string)`

**1단계: chartIdByMobile API 호출**
- **URL**: `https://sib.codns.com:3001/api/challenge/chartIdByMobile?mobile={휴대폰번호}`
- **목적**: 사용자의 검사 이력 조회
- **응답 예시**:
  ```json
  [
    {
      "chartID": "XD2500009",
      "receiptDate": "2025-09-08T00:00:00.000Z",
      "resultYN": "Y",
      "orderCode": "D0060"
    }
  ]
  ```
- **검증 로직**:
  - 배열이 비어있으면 → 403 Forbidden
  - `orderCode === ExamCode.DELAYED_ALLERGY` (D0060) 이고 `resultYN === "Y"` 인 검사 결과 찾기
  - 지연성 알러지 검사 결과가 없으면 → 403 Forbidden
  - 여러 개 있으면 가장 최신 것 선택 (receiptDate 기준)
  - 180일 경과 체크: `daysDiff > 180` → 403 Forbidden
  - **개선사항**: D0060 하드코딩 대신 `ExamCode.DELAYED_ALLERGY` enum 사용

**2단계: getIggLevels API 호출**
- **URL**: `https://sib.codns.com:3001/api/report/getIggLevels?chartId={chartID}`
- **목적**: 알러지 식품 상세 데이터 조회
- **응답 예시**:
  ```json
  [
    {
      "chartId": "BA2516182",
      "userName": "현문희",
      "level1": "아몬드,브라질너트,카카오",
      "level2": "머스타드(겨자),홍합,랍스터",
      "level3": "해당없음",
      "level4": "새우",
      "level5": "해당없음"
    }
  ]
  ```
- **데이터 변환**:
  - `level1` ~ `level5` 문자열을 파싱
  - 쉼표(`,`)로 분리하여 개별 식품으로 변환
  - "해당없음" 제외
  - `{ name: string, level: number }` 배열로 반환

### 9. 통계 요약 API 단순화 (Statistics Summary API)

#### 9.1 설계 방향 결정
- **기존 고민**: 통계 요약 데이터를 별도로 계산할지, 기존 통계 API 재사용할지
- **최종 결정**: **기존 5개 통계 API를 그대로 재사용**
- **이유**:
  1. **Single Source of Truth**: 점수 계산 로직이 1곳에만 존재
  2. **중복 계산 방지**: 이미 계산된 결과를 재사용 (계산 로직 2번 돌리지 않음)
  3. **유지보수성**: 점수 계산 방식 변경 시 1곳만 수정
  4. **데이터 일관성**: 상세 통계와 요약 통계의 수치가 항상 일치
  5. **프론트엔드 유연성**: 화면에서 원하는대로 데이터 조합 가능

#### 9.2 API 구현
- **엔드포인트**: `GET /api/tracking/statistics/summary?startDate=2025-10-27&endDate=2025-11-02`
- **파일**:
  - `src/tracking/dto/statistics/statistics.dto.ts` (StatisticsSummaryDto 단순화)
  - `src/tracking/services/statistics.service.ts` (getStatisticsSummary)
  - `src/tracking/controllers/statistics.controller.ts`

#### 9.3 DTO 단순화
**변경 전**: 복잡한 summaryCards 구조
```typescript
{
  period: '1week',
  dateRange: { ... },
  summaryCards: [
    { type: 'BEAUTY', score: ..., weeklyData: ... },
    { type: 'DIET', allergyFoods: ..., healthFoods: ... },
    ...
  ]
}
```

**변경 후**: 5개 통계를 그대로 포함
```typescript
{
  dateRange: { startDate: '2025-10-27', endDate: '2025-11-02' },
  beauty: BeautyStatisticsDto,      // 기존 API 응답 그대로
  diet: DietStatisticsDto,           // 기존 API 응답 그대로
  fasting: FastingStatisticsDto,     // 기존 API 응답 그대로
  sleep: SleepStatisticsDto,         // 기존 API 응답 그대로
  activity: ActivityStatisticsDto    // 기존 API 응답 그대로
}
```

#### 9.4 Service 로직 단순화
```typescript
async getStatisticsSummary(userId: number, startDate: string, endDate: string) {
  // Promise.all로 5개 통계 API를 병렬 호출
  const [beauty, diet, fasting, sleep, activity] = await Promise.all([
    this.getBeautyStatistics(userId, startDate, endDate),
    this.getDietStatistics(userId, startDate, endDate),
    this.getFastingStatistics(userId, startDate, endDate),
    this.getSleepStatistics(userId, startDate, endDate),
    this.getActivityStatistics(userId, startDate, endDate)
  ]);

  // 이미 계산된 결과를 그대로 반환 (추가 계산 없음)
  return { dateRange: { startDate, endDate }, beauty, diet, fasting, sleep, activity };
}
```

#### 9.5 장점
1. ✅ **프론트엔드 1번 호출**로 모든 통계 받음 (네트워크 효율)
2. ✅ **백엔드는 단순히 묶어주기만** (병렬 호출 + 반환)
3. ✅ **각 통계의 summary와 detailData 모두 제공**
4. ✅ **중복 로직 제거** (점수 계산을 2번 하지 않음)
5. ✅ **Single Source of Truth** (로직 변경 시 1곳만 수정)
6. ✅ **데이터 일관성 보장** (상세/요약 수치 항상 일치)
