### 2. KST/UTC 날짜 처리 근본 해결 ⏰

**문제점**: 
- 프론트엔드가 보내는 KST datetime 문자열 ("2025-11-07 20:00:00")을 백엔드에서 UTC로 파싱 후 다시 +9시간 추가
- 이로 인해 날짜가 하루 뒤로 밀려서 검증 실패
- 예: "2025-11-07 20:00:00" → UTC 파싱 → +9h → "2025-11-08 05:00:00" → 날짜 추출: "2025-11-08" ❌

**근본 원인**:
- `new Date("2025-11-07 20:00:00")`은 로컬 타임존 기준으로 파싱 (UTC로 취급)
- 기존 `extractDateFromDateTime` 함수가 여기에 또 +9시간 추가
- 이중 오프셋 문제 발생

**해결 방법**: 전역 KST 유틸리티 함수 구현

#### 2-1. kst-date.util.ts에 새로운 함수 추가

**추가된 함수**:
1. `parseKSTDateTime(datetimeString: string)`: 프론트 KST 문자열 → Date 객체
2. `extractKSTDate(date: Date)`: Date 객체 → KST 날짜 문자열
3. `getKoreanToday()`: 오늘 날짜 KST 기준으로 반환

**수정 파일**:
- `src/common/utils/kst-date.util.ts:122-176` - 새로운 유틸리티 함수 3개 추가

**핵심 로직**:
```typescript
export function parseKSTDateTime(datetimeString: string): Date {
  // "YYYY-MM-DD HH:MM:SS" 정규식 파싱
  const [, year, month, day, hour, minute, second] = datetimeString.match(/^(\d{4})-(\d{2})-(\d{2})\s+(\d{2}):(\d{2}):(\d{2})$/).map(Number);
  
  // 기존 createKSTDate 패턴 활용 (KST 시간 그대로 UTC Date 객체로 생성)
  return createKSTDate(year, month, day, hour, minute, second);
}

export function extractKSTDate(date: Date): string {
  // UTC 기준 날짜 추출 (우리는 KST 시간을 UTC로 저장했으므로)
  return date.toISOString().split('T')[0];
}

export function getKoreanToday(): string {
  const now = getNowKST();
  return extractKSTDate(now);
}
```
