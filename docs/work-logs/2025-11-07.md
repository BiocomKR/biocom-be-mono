## ✅ 완료된 작업

### 1. GKE 파일 업로드 API 400 에러 해결 (Critical!)
**문제점**: GKE 배포 환경에서 파일 업로드 API가 400 Bad Request 에러 반환

**증상**:
- 로컬 환경: 정상 작동 ✅
- GKE 환경: 400 에러 발생 ❌
- 클라이언트 응답:
```json
{
  "success": false,
  "statusCode": 400,
  "message": "파일 업로드 중 오류가 발생했습니다. 잠시 후 다시 시도해주세요.",
  "error": "Bad Request",
  "timestamp": "2025-11-07T01:43:19.000Z",
  "path": "/api/upload/image?relatedType=COLUMN"
}
```

**원인 분석**:
1. **실시간 로그 트래킹**으로 문제 지점 특정:
   - JWT 인증: 통과 ✅
   - ThrottlerGuard: 통과 ✅
   - Multer 파일 파싱: 통과 ✅
   - **Google Cloud Storage 업로드: 실패 ❌**

2. **근본 원인**:
   - `src/upload/upload.service.ts:29`에서 `process.env.GOOGLE_APPLICATION_CREDENTIALS` 사용
   - GKE ConfigMap에 해당 환경변수 **누락**
   - 로컬 `.env`에는 존재하지만 운영 환경에는 없었음

3. **역사적 원인 추적**:
```bash
# 커밋 이력 확인
git log --oneline -20 -- "infra-gcp/k8s/configmap.yaml"

# d740bff 커밋 (9월 29일)
# "refactor: ConfigMap 불필요한 환경변수 제거"
# - GOOGLE_CLOUD_api-dev-biocom 제거
# - 하지만 GOOGLE_APPLICATION_CREDENTIALS는 추가 안 함
# - GOOGLE_SERVICE_ACCOUNT_KEY_FILE만 존재
```

**해결 방법**:
- ConfigMap에 누락된 환경변수 추가
- 환경변수명 일관성 유지 (로컬과 GKE 동일)

**수정 파일**: `infra-gcp/k8s/configmap.yaml`
```yaml
# Before
GOOGLE_CLOUD_api-dev-biocom: "api-dev-biocom"  # 잘못된 이름
GOOGLE_CLOUD_STORAGE_BUCKET: "api-dev-biocom-uploads"
GOOGLE_SERVICE_ACCOUNT_KEY_FILE: "/app/secrets/key.json"  # 코드에서 사용 안 함
GCS_BUCKET_NAME: "api-dev-biocom-biocom-uploads"  # 중복

# After
GOOGLE_CLOUD_PROJECT_ID: "api-dev-biocom"  # 정확한 이름
GOOGLE_CLOUD_STORAGE_BUCKET: "api-dev-biocom-uploads"
GOOGLE_APPLICATION_CREDENTIALS: "/app/secrets/key.json"  # 코드에서 사용
GCS_BUCKET_NAME: "api-dev-biocom-uploads"  # 통일
```

**배포 및 적용**:
```bash
# ConfigMap 업데이트
kubectl apply -f infra-gcp/k8s/configmap.yaml
# configmap/biocom-api-config configured

# 파드 재시작 (환경변수 적용)
kubectl rollout restart deployment biocom-api -n biocom-api
# deployment.apps/biocom-api restarted

# 롤아웃 완료 대기
kubectl rollout status deployment biocom-api -n biocom-api
# deployment "biocom-api" successfully rolled out
```

**테스트 결과**:
- ✅ 400kb 이미지 파일 업로드 성공
- ✅ Google Cloud Storage 업로드 정상 작동
- ✅ 공개 URL 반환 확인

- **실제**: 처음부터 문제가 있었음
- 9월 29일 ConfigMap 정리 시 환경변수 누락
- 파일 업로드 기능이 GKE에서 **한 번도 제대로 작동한 적 없음**
- 로컬 테스트만으로는 발견 불가능

### 2. 환경변수명의 일관성
**Bad**:
```yaml
# 각기 다른 이름 사용
GOOGLE_SERVICE_ACCOUNT_KEY_FILE: "/app/secrets/key.json"
GOOGLE_CLOUD_api-dev-biocom: "api-dev-biocom"
```

**Good**:
```yaml
# 코드에서 사용하는 이름과 동일
GOOGLE_APPLICATION_CREDENTIALS: "/app/secrets/key.json"
GOOGLE_CLOUD_PROJECT_ID: "api-dev-biocom"
```

### 3. 로그의 부재는 문제의 신호
- UploadController 로그가 전혀 안 찍힘 → 컨트롤러 도달 전 실패
- Google Cloud Storage 초기화 로그 없음 → 초기화 실패
- **"로그가 없다"는 것 자체가 중요한 정보**
