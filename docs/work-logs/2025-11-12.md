### 1. 휴대폰 번호 Deterministic 암호화 구현
**문제 상황:**
- 기존: GCM 모드 + 랜덤 IV → 매번 다른 암호문 생성
- 결과: WHERE 절 검색 불가 (같은 휴대폰 번호를 찾을 수 없음)

**해결 방법:**
- AES-256-CBC 모드 + 완전 고정 IV 사용
- IV: `crypto.createHash('md5').update('biocom-mobile-fixed-iv-2025').digest()`
- 평문 `01056060746` → 항상 `eaXeLcIYoGrTupR/xS2oqg==` 로 암호화

**구현 위치:**
- `src/common/utils/crypto.util.ts`
  - `encryptDeterministic()` - 암호화
  - `decryptDeterministic()` - 복호화

**테스트 결과:**
```
입력: 01056060746
암호화: eaXeLcIYoGrTupR/xS2oqg==
복호화: 01056060746
✅ 10회 반복 테스트 - 모두 동일한 결과
```

### 2. Prisma Extension 암/복호화 로직 수정
**주요 이슈:**
- 조회 시 복호화를 하지 않아서 암호문 그대로 반환되는 문제 발견
- "미들웨어 쓰는 이유가 뭐겠어?" - 형님 피드백

**수정 내용:**
```typescript
// src/common/services/prisma.service.ts

// 조회 시 자동 복호화 (result 섹션)
result: {
  user: {
    mobile: {
      needs: { mobile: true },
      compute(user) {
        return user.mobile ? CryptoUtil.decryptDeterministic(user.mobile) : user.mobile;
      }
    }
  },
  phoneVerificationLog: {
    mobile: {
      needs: { mobile: true },
      compute(log) {
        return log.mobile ? CryptoUtil.decryptDeterministic(log.mobile) : log.mobile;
      }
    }
  }
}

// 저장/검색 시 자동 암호화 (query 섹션)
query: {
  user: {
    async findFirst({ args, query }) {
      if (args.where?.mobile && typeof args.where.mobile === 'string') {
        args.where.mobile = CryptoUtil.encryptDeterministic(args.where.mobile);
      }
      return query(args);
    },
    async create({ args, query }) {
      if (args.data.mobile && typeof args.data.mobile === 'string') {
        args.data.mobile = CryptoUtil.encryptDeterministic(args.data.mobile);
      }
      return query(args);
    }
    // findUnique, findMany, update, updateMany 등 모두 동일 패턴
  }
}
```

**최종 동작:**
1. 저장: 평문 → `encryptDeterministic()` → DB 암호문
2. 조회: DB 암호문 → `decryptDeterministic()` → 평문
3. 검색: 평문 WHERE → `encryptDeterministic()` → 암호문으로 검색

CREATE TABLE user_consents (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    agree_to_terms BOOLEAN NOT NULL,          -- [필수] 서비스 이용약관

    agree_to_privacy BOOLEAN NOT NULL,        -- [필수] 개인정보 수집

async phoneRegister(phoneRegisterDto: PhoneRegisterDto) {

## 🐛 해결한 주요 이슈

### 이슈 1: 암호화 알고리즘 선택 실패
**경과:**
1. 첫 시도: GCM + text 기반 IV → 비결정적
2. 두 번째 시도: GCM + 고정 IV → 여전히 비결정적
3. 최종 해결: CBC + 완전 고정 IV → 성공

**교훈:**
- GCM 모드는 인증 태그 생성 시 내부적으로 랜덤성이 있어 deterministic 암호화에 부적합
- CBC 모드 + 완전 고정 IV가 정답

### 이슈 2: Prisma Extension 복호화 누락
**증상:**
```typescript
// 잘못된 코드
mobile: {
  compute(user) {
    return user.mobile;  // 암호문 그대로 반환!
  }
}
```

**수정:**
```typescript
// 올바른 코드
mobile: {
  compute(user) {
    return user.mobile ? CryptoUtil.decryptDeterministic(user.mobile) : user.mobile;
  }
}
```

**교훈:**
- Prisma Extension은 저장 시 암호화 / 조회 시 복호화를 자동으로 처리하는 것이 핵심
- 미들웨어 개념을 제대로 이해하고 사용해야 함

### 이슈 3: 잘못된 암호화 값 전달
**문제:**
- 코드를 여러 번 수정하면서 암호화 알고리즘이 바뀜
- `QV+hVH3JEagZedv2Jlookw==` (GCM 모드) → `eaXeLcIYoGrTupR/xS2oqg==` (CBC 모드)
- 형님께 잘못된 값을 전달해서 혼란 발생

**교훈:**
- 암호화 알고리즘 변경 시 기존 테스트 값은 무효화됨을 인지
- 최종 확정 후 검증된 값만 전달해야 함
