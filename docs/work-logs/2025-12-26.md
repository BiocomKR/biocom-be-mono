## 1. 보안 강화 작업

### 1.1 ConfigMap에서 민감정보 제거
- **문제**: `DATABASE_URL`에 DB 비밀번호가 평문으로 노출
- **해결**: ConfigMap에서 `DATABASE_URL` 제거, `DATABASE_URL_OPTIONS`만 유지
- **변경 파일**:
  - `infra-gcp/k8s/overlays/dev/configmap.yaml`
  - `infra-gcp/k8s/overlays/prod/configmap.yaml`

### 1.2 Pod 시작 시 DATABASE_URL 동적 생성
- **구현**: Deployment에서 shell command로 DATABASE_URL 조합
- **특수문자 처리**: Node.js `encodeURIComponent()`로 비밀번호 URL 인코딩
- **변경 파일**: `infra-gcp/k8s/base/deployment.yaml`

```yaml
command: ["/bin/sh", "-c"]
args:
  - |
    ENCODED_PASSWORD=$(node -e "console.log(encodeURIComponent(process.env.DB_PASSWORD))")
    export DATABASE_URL="postgresql://${DB_USERNAME}:${ENCODED_PASSWORD}@${DB_HOST}:${DB_PORT}/${DB_NAME}?${DATABASE_URL_OPTIONS}"
    exec node dist/src/main.js
```

### 1.3 환경별 Secrets 파일 분리
- **생성**: `.env.secrets.dev`, `.env.secrets.prod`
- **삭제**: 기존 `.env.secrets` (통합 파일)
- **gitignore 업데이트**: `.env.secrets.*` 패턴 추가

## 5. 해결한 이슈

### 5.1 K8s 변수 치환 문제
- **문제**: `$(VAR)` 형식이 envFrom 값에서 작동 안 함
- **해결**: shell command의 `${VAR}` 형식으로 변경

### 5.2 비밀번호 특수문자 문제
- **문제**: `@`, `#`, `!` 등이 DATABASE_URL 파싱 오류 유발
- **해결**: `encodeURIComponent()`로 URL 인코딩

- **문제**: Docker 이미지에 python3 없음
- **해결**: Node.js로 URL 인코딩 처리
