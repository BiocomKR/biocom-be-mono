## 3. 영양제 배치 중복 실행 문제 해결

### 문제 발견
배치 로직 점검 중 심각한 문제 발견:
1. **중복 데이터 생성**: user_records 테이블에 동일한 데이터가 3배씩 생성됨
2. **record_type 오타**: `SUPPLEMENTS` (복수형) → `SUPPLEMENT` (단수형) 오류
3. **멀티 파드 환경 문제**: GKE 2개 파드 + 로컬 1개 = 총 3번 중복 실행

### 데이터 분석 결과

#### 중복 생성 패턴
| 날짜 | 예상 건수 | 실제 건수 | 중복 배수 |
|------|----------|----------|----------|
| 2025-11-30 | 3 | 6 | **2배** |
| 2025-12-01 | 3 | 18 | **6배** |
| 2025-12-02 | 3 | 15 | **5배** |
| 2025-12-03 | 3 | 15 | **5배** |
| 2025-12-04 | 3 | 15 | **5배** |
| 2025-12-05 | 3 | 15 | **5배** |
| 2025-12-06 | 3 | 15 | **5배** |
| 2025-12-07 | 3 | 12 | **4배** |

#### 생성 시점 분석
- `2025-12-01 01:00:00` (84건): CronJob 자동 실행 (월요일 00:10 UTC)
- `2025-12-01 10:02:58` (42건): 수동 실행 2회

### 근본 원인
1. **NestJS @Cron 데코레이터**가 각 파드에서 실행됨 (2개 파드 = 2번 실행)
2. **Kubernetes CronJob**도 동시에 실행됨 (1번 실행)
3. **로컬 개발 환경**에서도 실행됨 (1번 실행)
4. **총 3-4번 중복 실행**

#### C. DB UNIQUE 제약 추가
**파일**: `prisma/migrations/add_user_records_supplement_unique_index.sql`

```sql
CREATE UNIQUE INDEX IF NOT EXISTS user_records_supplement_unique
ON user_records (
  user_id,
  record_type,
  date,
  ((metadata->>'productId')::int)
)
WHERE record_type = 'SUPPLEMENT';
```

**효과:**
- 동일한 사용자, 날짜, 영양제에 대해 하나의 레코드만 존재 보장
- `skipDuplicates: true`와 함께 사용하여 안전한 배치 실행
- 서버 멈춤 없이 중복 데이터 자동 방지

#### D. record_type 오타 수정

**문제:**
- 배치 코드에서 `'SUPPLEMENTS'` (복수형)로 잘못 생성
- 올바른 값은 `'SUPPLEMENT'` (단수형)

**수정 SQL**: `prisma/migrations/fix_supplement_record_type.sql`
```sql
UPDATE user_records
SET record_type = 'SUPPLEMENT'
WHERE record_type = 'SUPPLEMENTS';
-- 결과: 21건 수정
```
