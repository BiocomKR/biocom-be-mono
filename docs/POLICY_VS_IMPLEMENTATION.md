## 👥 **사용자 상태 정의**

### **정책 정의서 기준**
1. **회원가입 이후 ~ 챌린지 구입 전** (신규회원)
2. **챌린지 구입 전/후 ~ 시작 전** (구매 완료)
3. **챌린지 시작 후** (활성 진행)

### **현재 구현 + 추가 정의**
```typescript
enum UserSubscriptionStatus {
  NEWCOMER = 'newcomer',           // 신규회원 (결제 안함)
  CHALLENGE_ACTIVE = 'challenge_active',  // 챌린지 진행 중
  SUBSCRIBER = 'subscriber'        // 월구독 회원
}
```

### **상태 전환 플로우**
```
신규회원 → 챌린지 구매&활성화 → 챌린지 활성화 회원
챌린지 활성화 회원 → 챌린지 완료 → 신규회원 (구독 권유)
신규회원 → 구독 구매 → 구독 회원
구독 회원 → 구독 만료 → 신규회원
구독 회원 → 챌린지 구매&활성화 → 챌린지 활성화 회원 (구독 병행)
```

## ⚠️ **수정이 필요한 부분**

### **🔴 높은 우선순위**

#### **1. 챌린지 시작일 설정 시스템**
**정책 정의서:**
```
- 시작일: 구매일 +30일 전까지 설정 가능
- 배송일: 시작일 -1일 (평일만)
- 종료일: 시작일 +20일
- 시작일 최종 지정 후 수정 불가
```

**현재 구현 이슈:**
- ❌ UserChallenge에 startDate, deliveryDate 필드 없음
- ❌ 시작일 설정/수정 로직 없음
- ❌ 평일 제약 로직 없음

**필요 작업:**
```typescript
// 새 테이블 또는 UserChallenge 확장 필요
interface ChallengeSchedule {
  startDate: DateTime;
  deliveryDate: DateTime;
  endDate: DateTime;
  isConfirmed: boolean;
  canModify: boolean;
}
```

#### **2. 권한 기반 접근 제어 시스템**
**정책 정의서:** 상세한 메뉴별 접근 권한 매트릭스

**현재 구현 이슈:**
- ❌ 컨트롤러에 권한 체크 로직 없음
- ❌ 사용자 상태 기반 기능 제한 없음

**필요 작업:**
```typescript
// 가드 또는 데코레이터 방식으로 권한 체크
@RequireSubscriptionStatus([UserSubscriptionStatus.CHALLENGE_ACTIVE])
@Get('restricted-feature')
```

#### **3. 설문 점수 계산 로직 통일**
**정책 정의서:** 이너뷰티 + 아우터뷰티 = 100점 만점
```
- 전혀 그렇지 않다: 12.5점
- 거의 그렇지 않다: 10점
- 보통이다: 7.5점
- 약간 그렇다: 5점
- 매우 그렇다: 2.5점
```

**현재 구현:** 0~-14점 감점 시스템
```typescript
// 현재: 100점에서 차감하는 방식
// 정책서: 직접 점수 부여 방식
```

### **🟡 중간 우선순위**

#### **4. 컨텐츠 접근 제한**
**정책 정의서:** 시작 전 강의는 미리보기만, 시작 후 전체 시청
**현재 구현:** 접근 제한 로직 없음

**현재 구현:** 기본 퀴즈 시스템만 존재

## 🚀 **신규 추가 필요 기능**

### **🔴 필수 추가 기능**

#### **1. 일일 기록 시스템 (8개 항목)**
**정책 정의서 요구사항:**

**이너뷰티 자가문진 (4항목):**
- 장: "속이 더부룩하거나 배가 불편했던 순간이 있었나요?"
- 대사: "손발이 차거나 에너지가 부족하다고 느껴졌나요?"
- 염증: "몸이 붓거나 평소보다 무겁고 피로한 느낌이 있었나요?"
- 면역: "입병, 목 따가움, 잔기침이 있었나요?"

**아우터뷰티 자가문진 (4항목):**
- 붓기: "아침에 얼굴이나 눈 주위가 평소보다 부은 느낌이 있었나요?"
- 수분감: "피부가 당기거나 건조하다는 느낌이 있었나요?"
- 유분감: "피지로 인해 얼굴이 번들거리거나 유분감이 느껴졌나요?"
- 트러블: "붉은기나 뾰루지 등 눈에 띄는 피부 트러블이 있었나요?"

**기타 기록:**
- 식단 기록 (사진 필수)
- 영양제 기록
- 간헐적 단식
- 수면 기록
- 활동 기록

**현재 구현:** UserRecord 테이블 존재하지만 8개 항목 구조 없음

#### **2. 통계 대시보드 시스템**
**정책 정의서 요구사항:**
- 이너뷰티 + 아우터뷰티 종합 점수 추이
- 식단 점수 (과민식품/고포드맵/가공식품 기준)
- 영양제 복용률 및 영양소 섭취량 그래프
- 간헐적 단식 성공률
- 수면 패턴 분석
- 활동량 통계

**현재 구현:** 기본 통계 기능 없음

#### **3. 식단 점수 시스템**
**정책 정의서 로직:**
```
과민식품(4-5단계) 섭취 개수별 점수:
- 0개: 좋음
- 1개: 양호  
- 2개: 주의
- 3개 이상: 나쁨

고포드맵 식품, 가공 식품도 동일 기준
종합 점수: 0-1개(좋음), 2-3개(양호), 4-6개(주의), 7개 이상(나쁨)
```

**현재 구현:** 식단 점수 로직 없음

#### **4. 영양제 관리 시스템**
**정책 정의서 요구사항:**
- 맞춤 추천 영양제 자동 등록
- 복용 시간 설정
- 바이오컴 영양제 DB 내장
- 타사 영양제 직접 입력
- 7일 연속 빙고 시 쿠폰 리워드
- 영양소별 섭취량 합산 그래프

**현재 구현:** 기본 구조 없음

### **🟡 추가 고려 기능**

#### **5. 구독 시스템**
**비즈니스 요구사항:**
- 월구독 자동결제
- 대부분 기능 해금 (챌린지 전용 제외)
- 구독 + 챌린지 병행 가능
